Issue #170 is not solved when using `server`, only when using `name` for destination
`ValidationDestination` is being used [here](https://github.com/argoproj-labs/applicationset/blob/v0.1.0/pkg/controllers/applicationset_controller.go#L560) to determine if we should remove the finalizer.  You can see in its implementation [here](https://github.com/argoproj/argo-cd/blob/master/util/argo/argo.go#L296), the entire function only does any validation when `dest.Name != ""`.  So when using `server` for the destination, the function passes and the finalizer is never removed.

### Additional contract requirements

- The ApplicationSet reconciler must remove the Argo CD resources finalizer from an Application whose destination does not correspond to any known cluster. A destination corresponds to a known cluster when the cluster's server URL equals the destination's server URL and, if the destination also names a cluster, that name equals the cluster's name. A destination that specifies both a cluster name and a server URL is not a valid destination, so its finalizer is removed.
- The public function `ListClusters(ctx context.Context, clientset kubernetes.Interface, namespace string) (*appv1.ClusterList, error)` in package `pkg/utils` (file `pkg/utils/clusterUtils.go`) returns the Cluster resources defined by the Argo CD cluster secrets in the given namespace, and returns a non-nil error when the underlying secret retrieval fails.
- The reconciler exposes the method `removeFinalizerOnInvalidDestination(ctx context.Context, applicationSet argoprojiov1alpha1.ApplicationSet, app *argov1alpha1.Application, clusterList *argov1alpha1.ClusterList, appLog *log.Entry) error` in package `pkg/controllers` (file `pkg/controllers/applicationset_controller.go`). It accepts the list of clusters and removes the Argo CD resources finalizer when the destination is invalid.
