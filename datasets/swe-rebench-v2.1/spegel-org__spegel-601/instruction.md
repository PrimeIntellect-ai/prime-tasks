Containerd hosts config are sorted and not in the specified order
### Spegel version

v0.0.23

### Kubernetes distribution

na

### Kubernetes version

na

### CNI

na

### Describe the bug

The order of hosts in the hosts.toml files in containerd config generated by the spegel configuration command do not preserve the order of previous config nor the order in arguments.
This is due to the fact that maps marshalled with the go-toml library are sorted by key.
The issue is that the order of the "hosts" table is important in containerd as hosts are tried in order of apparition in the file.

All current tests pass because it seems they take this fact into account.
You can try to switch the order of mirrors in input of a test without changing the expected output. The test will still pass while it shouldn't.

### Additional contract requirements

- Generated `hosts.toml` files must omit a standalone `[host]` header and must not end with a trailing newline.
- The mirrors passed to the configuration command must appear in the generated file in the order they were given, before any host tables carried over from a previous configuration.
- Host tables in the generated file must be written with single-quoted TOML strings, `key = value` assignments, comma-space separators in arrays, lexicographically ordered keys within each table, and one blank line between table sections.
- - Generated mirror host tables must use `capabilities = ['pull', 'resolve']` when tag resolution is enabled and `capabilities = ['pull']` when it is disabled.
