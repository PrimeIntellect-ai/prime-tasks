# This is a Feature Proposal

## Description

Context: When package individually is set to true, webpack entry should not be configured at all. This is currently the expected behaviour. It is however not explicit enough to the plugin user and it will fail with some other error.

Proposal: Throw an error when webpack entry is configured and package individually is set to true.

Related to:
* #266. See discussion [here](https://github.com/serverless-heaven/serverless-webpack/issues/266#issuecomment-341892898).

### Additional contract requirements

When individual packaging is enabled, a configured Webpack entry that differs from the entry automatically generated by the plugin for the service's functions must be rejected during validation, so it does not cause an unrelated downstream failure. The generated entry remains valid, including when supplied explicitly for backward compatibility.
