no-server-trailing-slash shows error for `/` for oas3
## Describe the bug

Using the below YAML I get this error
```
validating demo.yaml...
[1] demo.yaml:10:10 at #/servers/0/url

Server `url` should not have a trailing slash.

 8 |     url: https://demo.com/domain/path
 9 | servers:
10 |   - url: /
11 |     description: The Server
12 | paths:

Error was generated by the no-server-trailing-slash rule.
```

Reading up on the openapi specs this should actually be valid.

### Source
  * https://spec.openapis.org/oas/latest.html#fixed-fields
    * `servers` field name says
      > (...) If the servers property is not provided, or is an empty array, the default value would be a Server Object with a url value of /.


Looking into your oas3 rule `NoServerTrailingSlash` [HIDDEN] I think this needs to be adjusted to allow also a single `/` as root (same like in this PR but for openapi 3.x.x specs https://github.com/Redocly/openapi-cli/pull/162)

https://github.com/Redocly/openapi-cli/blob/e6f99e57da339d89bba7f4a1ba897282d7cebbd2/packages/core/src/rules/oas3/no-server-trailing-slash.ts#L7

### Additional contract requirements

- For OpenAPI 3, the no-server-trailing-slash rule must not report a server URL of exactly `/` as a trailing-slash violation.
- The rule must continue to report server URLs other than `/` that end in `/`.
