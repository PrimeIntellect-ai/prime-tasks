Support scoped packages
We are using GitHub Registry which currently only supports scoped packages. As a result, none of our packages can start with `bpmnlint-plugin-`. Is it possible to allow packages that are scoped, but start with that rule? An example would be `@myorg/bpmlint-plugin-my-org-rules`.

### Additional contract requirements

- Rule references used in a configuration are parsed by `Linter#parseRuleName(name, localPackage = 'bpmnlint')`, which returns an object `{ pkg, ruleName }`. `pkg` is the resolved NPM package name and `ruleName` is the rule's short name. When the reference carries no explicit package prefix, `pkg` is the supplied `localPackage` value (default `bpmnlint`). The supported forms are: built-in (`no-label`, `bpmnlint/no-label`), shortcut (`foo/no-label` resolves to `bpmnlint-plugin-foo`), full package (`bpmnlint-plugin-foo/no-label`) and scoped (`@scope/foo/no-label` and `@scope/bpmnlint-plugin-foo/no-label` both resolve to `@scope/bpmnlint-plugin-foo`). A reference that does not match any supported form throws `Error('unparseable rule name <…>')`.
- Configuration references used in an `extends` field are parsed by `Linter#parseConfigName(name)`, which returns an object `{ pkg, configName }`. `pkg` is the resolved package name and `configName` is the exported configuration name. The supported forms are: the default namespace (`bpmnlint:recommended` resolves to `bpmnlint`), plug-in shortcut (`plugin:foo/recommended` resolves to `bpmnlint-plugin-foo`), full package (`plugin:bpmnlint-plugin-foo/recommended`) and scoped (`plugin:@scope/foo/recommended` and `plugin:@scope/bpmnlint-plugin-foo/recommended` both resolve to `@scope/bpmnlint-plugin-foo`). A reference that does not match any supported form throws `Error('unparseable config name <…>')`.
