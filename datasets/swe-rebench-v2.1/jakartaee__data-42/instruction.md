Do we have the static factory methods for Pageable reversed?
I was looking at the [Pageable in Spring Data](https://docs.spring.io/spring-data/commons/docs/current/api/org/springframework/data/domain/Pageable.html) (static methods tab) and noticed that the primary pattern enabled by the static factory methods is to create `Pageable` for a particular page size `Pageable.ofSize(50)`, automatically starting on the first page, and to optionally select a different page `Pageable.ofSize(50).withPage(2)` if you didn't want the default first page.

To me, it does seem more natural to assume that more users will be interested in specifying a particular page size and defaulting to the first page than would be interested in choosing a particular page number and defaulting the page size, as we [currently have in Jakarta Data](https://github.com/jakartaee/data/blob/1f9ce811fdf51fdaa818e9ada9a2f919c149b112/api/src/main/java/jakarta/data/repository/Pageable.java#L122). We don't necessarily need to get rid of the `Pageable.page(pageNum)` method, but I'd like to add in the reverse pattern, either `Pageable.of(pageSize)` or `Pageable.ofSize(pageSize)` or `Pageable.size(pageSize)` because I expect it will be more commonly used and will make code more readable and less error-prone than the two argument `Pageable.of(long, long)` method.
