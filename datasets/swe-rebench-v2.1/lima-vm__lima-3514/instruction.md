Embedded json templates are failing jsonschema validation
### Description

The files do not match the limayaml definition:

```go
type LimaYAML struct {
        Base                  BaseTemplates `yaml:"base,omitempty" json:"base,omitempty" jsonschema:"nullable"`
...
        Images                []Image       `yaml:"images" json:"images"` // REQUIRED
```

```go
type BaseTemplates []LocatorWithDigest

type LocatorWithDigest struct {
        URL    string  `yaml:"url" json:"url"`
        Digest *string `yaml:"digest,omitempty" json:"digest,omitempty" jsonschema:"nullable"` // TODO currently unused
}
```

There is no alternative, for string only (no wrapper)

```yaml
minimumLimaVersion: 1.1.0

base:
- template://_images/ubuntu-24.10
- template://_default/mounts
```

```
- at '': validation failed
  - at '': missing property 'images'
  - at '/base': oneOf failed, none matched
    - at '/base': validation failed
      - at '/base/0': got string, want object
      - at '/base/1': got string, want object
    - at '/base': got array, want null
```

And it probably doesn't need to use "nullable" either?

```yaml
base: null
```

```yaml
- url: template://_images/default
  digest: null
```

It was mostly there for legacy (empty) yaml mappings.

### Additional contract requirements

The fix must make the embedded templates (including the documented `base` forms) pass JSON Schema validation:

- `images` is no longer required: it may be omitted or set to `null`, because images can be supplied later through `base`. Marshaling an empty `LimaYAML` must produce `{}` (i.e. `images` is omitted when empty).
- `base` accepts either a single string, or an array whose items are strings or `{url, digest}` objects.
- `LocatorWithDigest` accepts either a string or an object.
- The embedded templates and the documented `base` forms must pass the JSON Schema generated by `limactl generate-jsonschema`.
