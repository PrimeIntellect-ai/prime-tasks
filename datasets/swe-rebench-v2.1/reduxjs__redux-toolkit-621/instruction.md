`updateMany` ignores early updates if later updates have the same ID
The `updateMany` action generated by the `createEntityAdapter` function is not working as intended when there are multiple updates to the same entity.

Consider the following code:

```ts
const slice = createSlice({
  name: 'books',
  initialState: booksAdapter.getInitialState(),
  reducers: {
    bookAdd: adapter.addOne,
    bookUpdates: adapter.updateMany,
  },
});

// configure store and add books ...

store.dispatch(
  slice.actions.bookUpdates([
    { id: 1, changes: { title: 'New Title 1' } },
    { id: 2, changes: { title: 'New Title 2' } },
    { id: 1, changes: { author: 'New Author 1' } },
    { id: 2, changes: { author: 'New Author 2' } },
  ])
);
```

The outcome of that last statement should be that entity `1` has a title of "New Title 1" _and_ a new author of "New Author 1".  But what actually happens is that the `author` is changed but not the title.

The [docs](https://redux-toolkit.js.org/api/createEntityAdapter) say, "If `updateMany()` is called with multiple updates targeted to the same ID, they will be merged into a single update, with later updates overwriting the earlier ones."  That's a little ambiguous.  It could mean that the later updates should be merged with earlier updates (not conflicting if the fields are different), or that the later updates would completely replace earlier updates with the same ID.  It's doing the latter, but should do the former.
