### Additional contract requirements

Add a public function `evaluate_forward_ref(forward_ref, *, owner=None, globals=None, locals=None, type_params=None, format=Format.VALUE, _recursive_guard=frozenset())` in the `typing_extensions` module. It resolves a `typing.ForwardRef` to its concrete type, recursively evaluating forward references nested within the type hint, and otherwise mirrors `typing.ForwardRef.evaluate` for name resolution and caching. `owner`, if given, is the object (module, class, or callable) that held the annotation and is used to infer the namespaces for name look-ups; `globals` and `locals` may also be given explicitly, and explicitly passed namespaces take precedence over names inferred from `owner`. `type_params` is a tuple of type-parameter objects that are in scope. `format` is a member of the `Format` enum. When a name cannot be resolved and `format` is `Format.FORWARDREF`, the unchanged `ForwardRef` is returned; otherwise a `NameError` is raised.

The `typing_extensions` module must also expose the module-level name `_FORWARD_REF_HAS_CLASS`.

For invalid plain special forms, the `TypeError` message must match the patterns `Plain .*Protocol('>)? is not valid as type argument`, `Plain .*Generic('>)? is not valid as type argument`, `Plain typing(_extensions)?\.Final is not valid as type argument`, and `Plain typing(_extensions)?\.ClassVar is not valid as type argument`.

The `Format` enum must expose `Format.STRING`, and `get_annotations(..., format=Format.STRING)` must return annotation values as strings (for example, `{"a": "int"}` for an annotation `a: int`).


- On Python versions later than 3.10.0, the module-level `_FORWARD_REF_HAS_CLASS` value must be true.
