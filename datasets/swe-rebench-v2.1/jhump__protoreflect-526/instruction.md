protoparse: aggregate values in uninterpreted options differ from those generated by protoc
With the following .proto file, I get different results between protoc and the protoreflect package:

```
syntax = "proto2";

service ReproService {
  option (.api.service) = {
    collection: {
      name: "repro"
    }
  };

  rpc Repro(ReproRequest) returns (ReproResponse) {
    option (repro.policy) = {
      request_policies {
        selector: "repro"
      }
    };
  }
}
```

The difference in the ServiceDescriptorProto I’m getting is (-protoc +protoreflect):
```
  []*descriptor.ServiceDescriptorProto{
- 	s`name:"ReproService" method:<name:"Repro" input_type:"ReproRequest" output_type:"ReproResponse" options:<uninterpreted_option:<name:<name_part:"repro.policy" is_extension:true > aggregate_value:"request_policies { selector : \"repro\" }" > > > options:<uninterpreted_option:<name:<name_part:".api.service" is_extension:true > aggregate_value:"collection : { name : \"repro\" }" > > `,
+ 	s`name:"ReproService" method:<name:"Repro" input_type:"ReproRequest" output_type:"ReproResponse" options:<uninterpreted_option:<name:<name_part:"repro.policy" is_extension:true > aggregate_value:"{ request_policies{ selector: \"repro\" } }" > > > options:<uninterpreted_option:<name:<name_part:".api.service" is_extension:true > aggregate_value:"{ collection{ name: \"repro\" } }" > > `,
  }
```

You can see three kinds of differences:
1. curly braces
2. whitespace placement
3. colon presence (after “collection”)

I tried fixing this, but it’s not obvious to me what needs changing. I could make changes in the code to fix some of the 3 differences, but not all at the same time. Any ideas?
