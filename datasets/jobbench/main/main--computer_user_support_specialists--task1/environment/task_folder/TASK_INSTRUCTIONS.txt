You are a Computer User Support Specialist at AcmeCorp, a mid-size enterprise with 500+ employees. The VPN infrastructure has been experiencing widespread failures for three weeks, and VP of Technology Operations Sarah Mitchell has escalated the matter with specific directives (see mgmt_escalation_email.txt). Your job is to conduct a forensic reconciliation across the available data sources and produce change management deliverables.

Your task_folder contains a SQLite database (acmecorp_it_inventory.db), a VPN gateway diagnostic log (vpn_diagnostic_log.txt), an IT helpdesk ticket export (it_helpdesk_tickets.csv), the management escalation email thread (mgmt_escalation_email.txt), and a CAB change request template (cab_change_request_template.csv). You should also consult Cisco's official Secure Client 5.1 administrator guide on Cisco's website — specifically the troubleshooting chapter covering AnyConnect and Secure Client error codes — to support your analysis of the SSL/TLS failures observed in the gateway log. Brown University's public IT knowledgebase article on VPN troubleshooting may serve as a useful reference for end-user-facing documentation style.

Produce three deliverables. First, a cross-source incident reconciliation report (DOCX) that maps gateway log sessions against the database incident records and helpdesk tickets, identifying unreported issues and potential duplicates. The report must investigate every error pattern observed in the gateway log, determine how client version affects failure behavior, and address the specific questions raised in the management escalation email — including the split tunnel configuration discrepancy and whether the certificate situation and the SSL handshake failures share a root cause. Pay close attention to sub-version differences within the same client family, as they may exhibit different failure signatures.

Second, produce a single CSV file containing two CAB change requests using the provided template: one for the RADIUS/authentication infrastructure issues and one for the DNS resolution infrastructure issues. Each change request must cite specific session IDs and incident IDs from the source data as evidence. The DNS rollback plan should account for any tunnel routing discrepancies you identified in your reconciliation analysis.

Third, create a new SQLite database (vpn_executive_dashboard.db) with pre-computed summary tables for a management dashboard: a root cause summary with affected user counts, departments, mean time to resolution, and current status; a daily failure breakdown by error category covering the full date range present in the gateway log; and a client version correlation table showing failure types and success/failure rates.
