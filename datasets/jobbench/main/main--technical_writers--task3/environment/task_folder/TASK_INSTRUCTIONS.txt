TASK: API Documentation Reconciliation, Gap Analysis, and Standardization for TaskFlow API

You are a senior technical writer at a SaaS company that builds "TaskFlow," a project management platform. Engineering has provided you with current Markdown API docs written ad-hoc by multiple developers (taskflow_api_docs_current.md), an OpenAPI 3.0 YAML specification extracted from the codebase (taskflow_openapi_v2_extract.yaml), a production webhook delivery log (webhook_delivery_log.json), a per-endpoint documentation audit tracker (doc_audit_tracker.csv), and a REST API documentation template (restapidocs_combined_template.md). Your style guide should also draw on established API documentation practices from mature open-source projects, consulting public sources such as GitLab's REST API documentation guidelines as needed. Your manager wants you to reconcile these sources and produce publication-ready documentation.

Produce a discrepancy report as a CSV that cross-references the OpenAPI YAML spec against the existing Markdown docs, capturing every disagreement between the two sources. The audit tracker contains signal beyond what simple diff comparison reveals.

Create an API documentation style guide in Markdown (minimum 1500 words) that will govern all future TaskFlow API documentation. The style guide should be grounded in the conventions of the provided local references and adapted to TaskFlow's specific needs.

Rewrite the complete TaskFlow API v2 documentation in Markdown so that every endpoint conforms to your style guide. The rewritten docs must incorporate everything the OpenAPI spec knows that the current docs do not, and must resolve every issue surfaced by the audit tracker.

Produce a webhook event catalog as an HTML page by synthesizing the OpenAPI spec's declared event types with the production delivery log's observed event types. Each event entry should document the event name, description, trigger condition, example payload, and its provenance across these two sources.

Using the legacy v1 docs (taskflow_api_docs_current_v1.md) alongside your reconciled v2 materials, produce a developer-facing v1-to-v2 migration guide in Markdown that enables developers to upgrade their integrations.
