== AUTH STUFF ==
We use JWT tokens now. Changed from API keys last sprint (v2.1).
Token expires in 1 hour. Refresh tokens last 7 days.
Header format: Authorization: Bearer <token>
Login endpoint: POST /auth/login - takes email+password, returns tokens
Refresh: POST /auth/refresh - takes refresh_token in body

BUG: Sometimes 401 returns instead of 403 when token valid but perms wrong
TODO: Fix in next sprint (JIRA-4521)

== DATA ENDPOINTS ==

/datasets - GET list all datasets for user
params: page (default 1), limit (default 20, max 100), status (active|archived|all)
returns array of dataset objects

/datasets/{id} - GET single dataset
404 if not found or not owned by user

/datasets - POST create new dataset
body: { name: string (required, 3-100 chars), description: string (optional), tags: array }
returns created dataset with id

/datasets/{id} - PUT update dataset
same body as POST but all fields optional
returns updated dataset

/datasets/{id} - DELETE soft delete (sets archived flag)
returns 204 no content

/datasets/{id}/records - GET records in dataset
pagination same as /datasets list
params: sort (field name), order (asc|desc), filter (JSON encoded query)

/datasets/{id}/records - POST add record(s)
body can be single object or array for bulk insert
max 1000 records per request

/datasets/{id}/records/{record_id} - PATCH update single record
body: partial record object

/datasets/{id}/sync - POST trigger sync with external source
body: { source_id: string, mode: "full"|"incremental" }
returns job_id for async tracking

/jobs/{job_id} - GET check job status
response: { status: "pending"|"running"|"completed"|"failed", progress: 0-100, error: string|null }

== ERROR CODES ==

400 - bad request (validation failed) - body has "errors" array with field-specific messages
401 - not authenticated
403 - forbidden (authenticated but not authorized)
404 - not found
409 - conflict (e.g., duplicate name)
422 - unprocessable entity (business rule violation)
429 - rate limited (100 req/min for free tier, 1000 for pro)
500 - server error (we log these, include request_id in response for support)

== RESPONSE FORMAT ==

All responses wrapped:
{
  "success": true|false,
  "data": <payload>|null,
  "error": null|{ "code": "ERR_CODE", "message": "Human readable", "details": {} },
  "meta": { "request_id": "uuid", "timestamp": "ISO8601" }
}

== WEBHOOKS (v2.2 feature) ==

POST /webhooks - create webhook
body: { url: string, events: ["dataset.created", "dataset.updated", "sync.completed", "sync.failed"], secret: string (optional, for HMAC signing) }

GET /webhooks - list webhooks
DELETE /webhooks/{id} - remove webhook

Webhook payload:
{
  "event": "event.type",
  "timestamp": "ISO8601",
  "data": { <event specific> }
}

If secret provided, we send X-Webhook-Signature header with HMAC-SHA256 of body

== RATE LIMITS ==

Free tier: 100 requests/minute, 10000/day
Pro tier: 1000 requests/minute, unlimited daily
Enterprise: custom

Headers returned:
X-RateLimit-Limit: <max>
X-RateLimit-Remaining: <remaining>
X-RateLimit-Reset: <unix timestamp>
