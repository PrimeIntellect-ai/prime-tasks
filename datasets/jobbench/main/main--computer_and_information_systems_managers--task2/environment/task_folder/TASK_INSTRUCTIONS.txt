You are the IT Director at Meridian Technologies. The CIO has flagged conflicting signals in Q4 operations: incident volumes rose while infrastructure spending exceeded forecasts, yet several approved projects remain under-executed. She wants a unified risk-based analysis that reconciles operational, security, and financial data into a defensible infrastructure rationalization plan for the board.

Your incident log (ITSM_incident_data_q4.csv) and asset inventory (IT_Infrastructure_Inventory.xlsx) track configuration items under different conventions. Reconcile these sources to build a cross-referenced view of incident activity against asset health. Identify the top 10 assets driving incident volume and assess what operational or infrastructure factors explain the pattern. Reassignment behavior across incident categories often reveals systemic process gaps; surface those as well.

From the reconciled data, build a risk-weighted migration plan for underutilized or aging on-premise infrastructure. Assets flagged as Critical should generally be excluded from migration unless incident frequency justifies the risk. The Cloud Migration Phase 2 project (PRJ-2024-041) funds this effort; determine how much of its approved budget remains available given existing cloud operations reflected in the budget data. Locate AWS's legacy Excel workbook "Amazon_EC2_Cost_Comparison_Calculator.xls" (Amazon Web Services, revised February 1, 2010) and use its embedded historical prices as the fixed pricing benchmark for this exercise. Use the workbook to estimate migration TCO and flag any candidates where cloud costs would exceed current on-premise spend. The Zero Trust Network Architecture rollout (PRJ-2024-042) is still in progress and will reshape network segmentation; sequence migration candidates accordingly where relevant.

Map the incident categories with the worst reassignment performance to the NIST Cybersecurity Framework 2.0 subcategories that address those process failures, using the official NIST CSF 2.0 Core spreadsheet. Cross-reference each gap against the pending project portfolio to determine coverage; where no project exists, estimate the remediation cost and flag the gap as unbudgeted. Produce the gap register as gap_register.csv with fields: Gap_ID, NIST_Subcategory, Related_CI_Category, Severity, Mapped_Project_ID, Estimated_Cost, Remediation_Timeline.

Consolidate everything into Q4_Infrastructure_Rationalization.xlsx with four sheets: Reconciliation (incident-vs-inventory cross-reference with discrepancy annotations), Migration_Plan (ranked candidates with current and estimated cloud costs, risk flags, and action recommendation), Gap_Register (NIST gap data with red conditional formatting for unbudgeted high-severity items), and Executive_Summary (5–7 prioritized board-level recommendations, each tied to a quantified financial impact and implementation quarter).
