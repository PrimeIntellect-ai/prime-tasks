You are the lead technical writer at a company that provides the Petstore REST API platform. The v3.1.0 release shipped to production with breaking changes that were never documented, resulting in a spike in support tickets and enterprise customer escalations. Your mandate is an immediate documentation overhaul, prioritized by real customer impact.

Your first deliverable is a customer-facing migration guide (migration_guide_v3.1.0.md) for v3.1.0. The guide must address every breaking change introduced in this release — cross-reference the changelog, usage metrics, and support ticket data to determine how to structure and prioritize coverage. The guide must function as a standalone document: a developer reading only this guide should have everything needed to assess SDK compatibility and migrate successfully.

Your second deliverable is a revised API reference (revised_api_reference.md) that replaces the existing draft. Resolve every issue raised in the documentation review feedback, incorporate all undocumented changes from the changelog, and align the documentation with conventions from the Google developer documentation style guide highlights page and the Microsoft Writing Style Guide reference documentation guidelines page. Apply the company terminology standards consistently. Where support tickets reveal documentation-caused failures, surface these directly in the relevant endpoint sections. Endpoints with elevated error rates warrant enhanced troubleshooting coverage.

Your third deliverable is a documentation impact analysis (doc_impact_analysis.csv) that maps every documentation gap to its business impact. Each row should correlate the source issue, affected endpoint, related support tickets, quantified usage impact, a priority score (P0–P3) with data-driven justification, and whether the issue involves a terminology violation. Columns: issue_source, issue_id, endpoint, description, related_tickets, affected_consumers, error_rate_pct, priority, priority_justification, terminology_violation.

All deliverables must demonstrate professional judgment in synthesizing data across formats and resolving ambiguity where ticket descriptions do not perfectly align with changelog entries.
